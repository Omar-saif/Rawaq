## Project Overview

**Rawaq (رواق)** is a premium Islamic fashion + Arabic perfume e-commerce platform targeting
the Saudi Arabian market and the global Muslim consumer base. The brand identity centers on
deep navy (#0B1B3D) and gold (#C9A96E) with bilingual (English/Arabic) presentation.

## i18n Approach

**Library**: `next-intl` v3.x

**Strategy**: `localePrefix: "always"` — all routes are prefixed:
- English: `/en/...` (default locale)
- Arabic: `/ar/...`

**RTL**: The `[locale]/layout.tsx` sets `dir="rtl"` on `<html>` when locale is `"ar"`.
All CSS uses logical properties (`margin-inline-start`, `padding-inline-end`, etc.)
instead of `left`/`right` to support automatic RTL mirroring.

**Translation files**: `messages/en.json` and `messages/ar.json`

---

## Auth Approach

**Strategy**: Custom JWT with httpOnly cookies (no NextAuth.js dependency)

- Passwords hashed with `bcryptjs` (12 rounds)
- Sessions signed with `jose` (HS256, 7-day expiry)
- Cookie name: `rawaq_session`
- Cookie flags: `httpOnly`, `secure` (prod), `sameSite: lax`
- Guards: `requireAuth()` and `requireAdmin()` in `lib/utils/session.ts`

**Decision**: Chose custom JWT over NextAuth because:
1. The app has guest checkout (no OAuth needed initially)
2. Simpler dependency surface
3. Easier SSLCommerz webhook validation in Phase 11
4. Can add OAuth providers later without migrating session strategy

## API Error Shape

All API endpoints return errors in this shape:
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message",
    "details": {}
  }
}
```

Success responses:
```json
{
  "data": {},
  "meta": { "page": 1, "pageSize": 20, "total": 100, "totalPages": 5 }
}
```

## Category attributeSchema Shape

The `Category.attributeSchema` JSON field stores an array of attribute definitions:

```typescript
type AttributeDefinition = {
  key: string;       // e.g. "fabric", "scent", "size", "volume"
  label: string;     // e.g. "Fabric Type", "Scent Notes", "Size (cm)", "Volume"
  labelAr?: string;  // Arabic label
  type: "text" | "select" | "multiselect" | "range" | "boolean";
  options?: string[];  // for select/multiselect
  unit?: string;       // e.g. "cm", "ml" for range/numeric types
};
```

## Architectural Decisions Log

> Format: `[Task X.X] Decision made — reason`

- [Task 0.1] Initialized Next.js 16 (latest stable) with App Router, TypeScript, Tailwind v4 — latest LTS stack chosen for longevity
- [Task 0.2] Used Tailwind v4 CSS-first config (`@theme inline` in globals.css) instead of `tailwind.config.ts` — v4 generates classes from CSS variables, no JS config needed
- [Task 0.2] Added `brand-gold: #C9A96E` alongside `brand-navy` — color pulled from Rawaq logo emblem for premium feel
- [Task 0.3] Chose `next-intl` with `localePrefix: "always"` — cleanest App Router integration, explicit locale in URLs aids SEO
- [Task 0.3] Chose `Noto Naskh Arabic` for Arabic font — best Arabic web font coverage on Google Fonts for this script style
- [Task 0.4] API routes at `/app/api/` are NOT locale-prefixed — middleware matcher explicitly excludes `/api` paths
- [Task 2.1] Chose custom JWT (jose) + httpOnly cookies over NextAuth — simpler for guest checkout, no OAuth needed initially, easier webhook auth in Phase 11
- [Task 1.3] Added `nameAr`/`titleAr`/`descriptionAr` bilingual fields directly on Category/Product models — avoids a separate translations table for simplicity; can be migrated to a proper i18n table if more languages are needed
- [Task Hero] Added `Slide` model — replaces earlier product/category flag-based home hero approach; slides are fully managed from `/admin/slides` with drag-to-reorder, isActive toggle, and optional `startsAt`/`endsAt` schedule fields so seasonal banners auto-expire without code changes
- [Task Pixel] Abstracted Meta Pixel into a dedicated `fpixel.ts` utility and `CookieConsentBanner` — ensures GDPR compliance and centralizes CAPI readiness without cluttering product components
